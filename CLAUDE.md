# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

"MuscleNote", a personal gym workout tracker: a **native Android app** (Kotlin + Jetpack Compose) in `android-app/`, French by default with English. It is installed from the APKs of the GitHub Releases (users follow them with Obtainium); publishing on the Google Play Store is **not** planned, so store-compliance work is out of scope. The app is **offline**: no account, no user data ever sent. Its only network request is the update check (SPEC § 3.17, D25), which is why it holds the `INTERNET` permission.

**`SPEC.md` is the single reference** for behaviour, data format, theme, strings and decisions (§ 11; implementation status in § 13). Identity: `applicationId`/namespace `com.musclenote.android`, label « MuscleNote », minSdk 26, compile/targetSdk 37, portrait only.

The app replaced an earlier Expo / React Native app (`com.musclenote.app`), removed from the repo but kept at the tag **`expo-final`** (`git show expo-final:artifacts/mobile/<path>`). SPEC paths such as `constants/i18n/fr.ts` refer to that tag. Users move their data over by sharing the Expo app's JSON backup to the native app (SPEC § 5.5); the backup keys keep the legacy `@gymtracker_` prefix for that reason.

## Build, tests, releases

- Gradle Kotlin DSL + version catalog (`android-app/gradle/libs.versions.toml`), committed wrapper (checksum-pinned `distributionSha256Sum`). AGP 9 compiles Kotlin itself ("built-in Kotlin"): **never apply `org.jetbrains.kotlin.android` in a module** — the root build only declares it `apply false` to pin the Kotlin version (keep it equal to the Compose compiler plugin version).
- There is no local Android SDK on the dev machine: builds and tests run in CI. Locally with an SDK, from `android-app/`: `./gradlew :app:testDebugUnitTest` (JVM tests), `./gradlew :app:assembleDebug`.
- `.github/workflows/release.yml` runs on every push to `main` touching `android-app/**` (or the workflow itself): JVM tests, signed release APK (`versionName = 1.0.<run_number>`, `versionCode = 1000 + run_number` — above every former `v0.1.*` pre-release; keystore decoded from secrets into `$RUNNER_TEMP`, passed through `ANDROID_KEYSTORE_PATH` / `ANDROID_KEYSTORE_PASSWORD` / `ANDROID_KEY_ALIAS` / `ANDROID_KEY_PASSWORD`), signature check, then a normal (latest) GitHub Release `v1.0.<run_number>` with `MuscleNote-v1.0.<run_number>.apk`. Follow with `gh run watch`, debug with `gh run view --log-failed`. The repo is public: never print signing details in CI logs.
- Tests: JVM unit tests in `app/src/test/` target the pure rules and the repositories (`unitTests.isReturnDefaultValues = true` because some code logs through `android.util.Log`); `StringResourcesTest` checks that FR and EN have the same keys and positional arguments.

## Architecture (`android-app/app/src/main/java/com/musclenote/android/`)

- Strings: `res/values/strings.xml` (FR, default) + `res/values-en/strings.xml`, keys converted from the Expo app's `constants/i18n/*.ts` (SPEC § 9.4). Language = system language, overridable FR / EN through `AppCompatDelegate.setApplicationLocales` (`MainActivity` is an `AppCompatActivity`).
- Theme tokens: `ui/theme/Color.kt` (`MuscleNoteTheme.colors`, dark and light palettes, choice System / Light / Dark in preferences), Inter through Google downloadable fonts; muscle-group / fixed colours keep their base value for fills, borders and curves, but text and icons go through `MuscleGroup.textColor` / the `…OnLight` variants (darker shade in the light theme, SPEC D23). The chosen theme is also handed to the system (`ui/theme/SystemNightMode.kt`, Android 12+) so the splash follows it. Icons: Material Symbols vectors in `res/drawable`. Charts: the shared Canvas `ui/components/LineChart.kt` (SPEC § 2.13); date/number display helpers (`DateFormats`, `formatNumber`, `formatInteger`) in `ui/components/DisplayNames.kt` — always format with `appLocale()` (the locale of the displayed texts, `data/util/AppLocales.kt`, French when the system language is neither FR nor EN), never `locales[0]`.
- Data: one repository per domain in `data/repository/` (`StateFlow` + `Mutex`, one `JsonDocument` file per document in `filesDir/data/`, atomic writes, unreadable files set aside as `*.corrupt-<ms>.json`); pure business rules live beside them (`data/workout/WorkoutRules.kt`; statistics — streak, gym time, volume, 1RM, per-exercise history — in `WorkoutStats.kt`, Progrès tab calculations (§ 3.10) in `data/progress/ProgressStats.kt`, weigh-in rules in `data/nutrition/BodyWeightRules.kt`, all counting completed sets only) and are what the JVM tests target. Device-only settings (not in backups) go to `local_preferences.json` via `PreferencesRepository.localPreferences` (migrate-card dismissal, and a copy of the in-app language that `withAppLocale()` reads before Android 13, when AppCompat only knows it once an activity exists). Screens never keep their own copy of persisted data and call repository mutations through `AppContainer.launchMutation { … }` (undispatched start on the fair `Mutex`, so keystrokes apply in order and survive leaving the screen). The in-progress session is written with a 300 ms debounce and flushed on `ON_STOP`.
- Notifications (`notifications/`, shared by the rest timer and the supplement reminders): `AppChannel` (the three SPEC § 7.1 channels, names re-applied in the app language at app start and every activity creation), `ExactAlarms` (exact `RTC_WAKEUP`, inexact fallback), `AppNotifications.post` (silently skipped when notifications are denied), texts built through `Context.withAppLocale()`. Rest timer: `RestTimerRepository` (one rest, `rest_timer.json`; Android effects behind `RestTimerEffects`, a no-op in JVM tests) + `RestTimerNotifier` + `RestTimerReceiver`; the end alarm is the only source of the « rest finished » event, and `AppContainer.endWorkout()` / 24 h finalisation stop the rest.
- Supplement reminders (SPEC § 7.3): pure rules in `data/nutrition/` (`NutritionRules`, `ReminderSchedule` — next local wall-clock occurrence, DST-safe), Android side `SupplementReminderScheduler` behind the `SupplementReminders` interface (serial queue re-reading the latest supplements; alarm identity = `musclenote://reminder/{supplementId}/{reminderId}`), `SupplementReminderReceiver` (re-reads, notifies, reschedules tomorrow) and `ReminderResyncReceiver` (boot, package replaced, time/time-zone change, exact-alarm permission). `NutritionRepository` syncs alarms after every supplement change; `AppContainer` does a full resync at start-up and after an import. The current local day is `AppContainer.currentDay` (midnight timer, foreground, time-zone change); UI reads it through `rememberToday()`.
- Backup & export (Paramètres, `ui/settings/BackupViewModel.kt`): JSON v2 backup through `data/backup/` (`BackupWriter`; `BackupReader` = parse → version check → per-key validation → migrations → normalisation, v1 from the Expo app still imported) and `AppContainer.importBackup`, which also receives files shared by other apps (`SEND`/`VIEW` intent filters on `MainActivity`); CSV export is the pure `data/export/CsvExport.kt` (headers/format supplied by `CsvExportTexts`). Files are shared from `cacheDir/exports/` through the `FileProvider` (`res/xml/file_paths.xml`).
- Update check (SPEC § 3.17, D25): only when the app was not installed by an update manager (`update/InstallSource.kt`: Obtainium, or the Play Store name Obtainium can borrow through Shizuku). `UpdateRepository` (`update_check.json`, not in backups) reads the latest release through `ReleaseSource` (`update/GitHubReleaseSource.kt`: one anonymous `GET` to the GitHub API, `HttpURLConnection`, no extra dependency); pure rules (version comparison, daily schedule, 1 h retry after a failure, JSON parsing) in `data/update/UpdateRules.kt`. Checked on `AppContainer.onAppForeground`; shown as `UpdateBanner` on Home (dismissable per version) and `UpdateCard` in Paramètres (check now / download). « Download » opens the APK in the browser; the app never downloads or installs anything itself.
- Crash reports (SPEC § 10.9): `CrashHandler` is installed first in `MuscleNoteApplication.onCreate`, writes `filesDir/crashes/crash-<ms>.txt` through the pure `data/crash/CrashReports.kt` (5 most recent kept), flushes the in-progress session, then delegates to the default handler; Paramètres shows `CrashReportCard` only when a report exists (share the latest / delete all). Nothing is sent over the network.
